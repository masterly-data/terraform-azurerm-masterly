### Changed

- **With `builtin_auth_api`, the recovery fallback `builtin_auth_recovery_until` now turns `ca-api`'s built-in authentication off too, and every write to `ca-api`'s auth configuration is alerted (ADR 0117, amended 2026-11-02, item 5).** Under an Entra outage neither ca-recovery's nor the frontend's workload-identity token can be issued, so `ca-api`'s gate would refuse every call; while the window is open, the api's `authConfigs/current` has `platform.enabled = false` alongside the frontend's, and the first plan after the time turns both back on. The window's bounds are unchanged: at most 60 minutes, `builtin_auth` set, and a network restriction in front of `ca-frontend`. Only the gates change: the rest of both configurations, and `ca-api`'s and `ca-workers`' ingress and environment, are as with the window closed, so the application's own authentication stays in front. **An install with `builtin_auth_api = true` plans one new activity-log alert**, `azurerm_monitor_activity_log_alert.builtin_auth_api_config_write[0]` (`alert-<prefix>-api-auth-config-write`), which fires on every write to `ca-api`'s auth configuration (the disable, the restore, or a change outside Terraform) and notifies the install's action group; it exists whenever the switch is on, not only during a window. The frontend's alert, `alert-<prefix>-frontend-auth-config-write`, keeps its address and is not replaced. Without `builtin_auth_api`, nothing changes. See `docs/identity.md`, "Recovery fallback".
