### Added

- **`outbound_allowlist` output: what each subnet reaches outside the VNet (ADR 0120 §5).** A map keyed by each environment the install has (`aca` until `retire_runtime_environment`, `front`, `app`, `workers`, and `core`, `outbound` and `extension` with their add-ons), each a list of entries with `destination`, `kind` (`fqdn` or `service_tag`), `protocol`, `ports`, `why` and `source`. Every subnet carries the Container Apps platform set (Microsoft Container Registry, Microsoft Entra ID and Azure Monitor, from Microsoft Learn as read on 2026-11-23, and Azure management, which ADR 0120 §5 adds) and the image registry unless `registry_private_endpoint`; Docker Hub, the identity provider, the certificate vaults, a public Key Vault or Service Bus namespace, Communication Services, your own Postgres and Masterly's control plane sit only on the subnet where the workload that reaches them runs, so `front` never lists a data endpoint. It holds hosts and ports only, never a URL's credentials, and is not sensitive. The module still writes no outbound NSG rule or route from it. See `docs/networking.md`, "The outbound_allowlist output".
- **`deployment_stamp` output (ADR 0120 §8):** `module_version` (MANIFEST.json's `latest`), `release_ring`, `capacity_profile`, `add_ons`, `environments` and `database_provider_profile` (`starter` or `byo-db`, the install's own database only). Not sensitive, and it carries no URL.
- **`release_ring` input (ADR 0107):** `canary`, `beta` or `stable` (the default), reported in `deployment_stamp` and nowhere else. It is a declaration: your licence's `release_ring` claim decides what the install may run, and the module does not check one against the other. It is not `release_channel`. An upgrade plans no change.

### Documentation

- `docs/networking.md`: "What your firewall must admit" is per subnet and gains an Azure management row, the "No outbound rules" paragraph points to the new output, and the add-on environments' core row names the platform set and the registry it still reaches. `release_channel`'s description now says it is not `release_ring`.
